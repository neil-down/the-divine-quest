# Changelog — The Divine Quest

## v1.0.2 — Robustness Audit: Battle, Puzzle & Co (2026-09-24)
Verifies the user's skepticism: several legacy mechanics were crash-prone or silently dead. Each defect was reproduced under real-execution jsdom, fixed at source, and driven to green by new smoke probes.
- **Battle hardening** (`battle-system.js`): on-screen skills/intercession stay clickable during the 3 s victory/defeat pause — late clicks hit a removed overlay (`null` read) and could double-pay rewards. Now `battleEnded`/`inBattle` guards in victory/defeat/flee + `endBattle`, null-safe log writes, and a mount guard in `enemyTurn` (missing `#battle-overlay` → return). **Battle-hit VFX re-wired**: enemyTurn now dispatches a `battleHit` CustomEvent (visual-effects/audio consume it) — the old `battleEncounters.useSkill/…` hooks targeted a wrong/wrong-object global and never fired.
- **Puzzle fixes** (`puzzle-system.js`): the `solas_match` puzzle's options carry only `correct` (no `effect`) → clicking it threw `TypeError` (`choice.effect.faith`); `creed_match` had no render *or* hint case → blank, unsolvable. New `submitAnswer(choiceIndex)` handles `correct`-flagged choices, `makeChoice` dispatches both option flavors (legacy `effect` unchanged), and `showPuzzle` gains the `creed-match` render case + a safe default fallback; hints cover both types.
- **VFX/SFX actually fire now**: `visual-effects.js` one-shot +1000 ms DOMContentLoaded hooks could never see battle/puzzle/progression (they init +2000/+3000/+4000 ms) — replaced by a 250 ms retry loop (≤8 s) wiring `puzzleSystem.solvePuzzle` + `progressionSystem.onLevelUp`, kept ripple/chapter hooks, and consumes `battleHit`. `audio.js` hook for the defeat SFX pointed at `battleEncounters.defeat` (never a thing) and `tryHook` stopped on its first success, stranding every later sound — defeat now listens on the `battleDefeat` CustomEvent.
- **Settings UI reachable** (`settings.js`): the gear button/panel were never injected. Bootstrap now runs `window.settings.injectUI()` on `DOMContentLoaded`; gear given `id="settings-toggle"`.
- **Nightmare scoping fixed** (`nightmare-system.js`): `endNightmare`'s blanket `querySelectorAll('.fixed.inset-0')` nuked every full-screen overlay (incl. the battle overlay + its own success screens); `drainSanity` read a `#sanity-bar` that was never created. All nightmare overlays are now tagged `data-tdq-nightmare="1"`; cleanup targets only that scope (+`#unmaking-overlay`); success flows reordered so `endNightmare` runs before overlays are appended; `endUnmaking` gains a re-entry guard; sanity bar rendered in the loop-break overlay; entities get a dedicated `nightmare-entity` class so cleanup can't remove the battle enemy.
- **Milestone/progression fix** (`progression-system.js`): the Act I "boss" track read `window.battleEncounters.currentEnemy` (never set) so `bossesDefeated` never advanced → now reads `window.battle.currentEnemy`.
- **Infinite-loop cleanup** (`infinite-loop.js`): `criticalRealityFailure` started a 0.1 s infinite CSS animation that never reset → now auto-cleared after 1.2 s.
- **Enhancements** (`enhancements.js`): `endMeditation` returned before guarding `#meditation-area` (throw) and leaked its interval when the modal was closed manually.
- **UI occlusion resolved**: bottom-right stack overlapped — audio mute (16px) covered Devotions; now mute at right 144px, ambient 208px, the settings gear 272px (all bottom 16px, z 9999). Bottom-left ritual (→ bottom-32) and study-guide (→ bottom-44) no longer cover faction/nightmare panels.
- **i18n/build hygiene**: 6 superseded duplicate translation keys removed (cosmetic esbuild warnings eliminated; no runtime change).
- **Smoke harness grew and hardened**: battle driver now actually runs a fight (`useSkill('prayer')` loop against Shadow of Doubt; `smite`'s 1-turn cooldown was doubling — the old probe could never win), asserts win + reward + double-victory block; puzzle probes render/solve both creed-match and solas-match and assert no-crash on a wrong answer; settings probe reaches gear and toggles the panel; nightmare probe proves foreign `.fixed.inset-0` overlays survive `endNightmare` while tagged ones die; corner-widget spacing asserted. Fixed a harness bug that double-fired `DOMContentLoaded` (jsdom fires it naturally; manual dispatch created duplicate Settings instances/buttons).
- **NEW browser-verification suite** (`browser-smoke.mjs`, Playwright + headless Chromium, `npm run browser:smoke`): serves `dist/` on a localhost static server and drives a real browser — boots the story, opens/closes Settings, solves creed-match and solas-match via real DOM clicks, watches the puzzle-solve VFX append live elements, wins a real battle with '🙏 Prayer' clicks, verifies the double-victory guard, and asserts no corner-widget overlaps at 390×844 and 1280×800. Screenshot written to a temp dir. **jsdom couldn't see the DOM-rendered bugs this suite caught**:
  - `PuzzleSystem.showPuzzle()` never set `this.currentPuzzle` (only `checkPuzzle()` did) — any direct `showPuzzle()` call left it null and a click crashed with `Cannot read properties of null (reading 'options')`. The jsdom smoke had masked it by pre-setting `currentPuzzle`.
  - `VisualEffectsEngine.getOverlayContainer()` matched the *first* `.fixed.inset-0.z-50` in DOM order — the hidden Settings panel — so puzzle-solve rings/orbs rendered inside an invisible overlay. Now prefers open `#puzzle-overlay`/`#battle-overlay`, then any visible `.fixed.inset-0.z-50`, else the persistent container.
- **QA**: build clean (0 warnings); jsdom smoke green `{"errors": [], "total": 0}` exit 0 ×2; **browser smoke green 21/21 probes, 0 console/page errors, exit 0**, screenshot capture verified. Version bumped 1.0.1 → **1.0.2** (`window.APP_VERSION`, package.json).
